# v0.1.0-beta.2 limited technical beta

Published limited technical Beta maintenance release. Use synthetic or disposable data with a
separately verified independent recovery recipient; production secrets are not supported.

## Change since beta.1

- Fixed the standard age `identity-v1` path for configurations containing multiple plugin identity
  files. A valid v2 phone stanza that does not target the current identity is now reported as an
  ordinary identity miss, so age can continue to a later configured identity.
- The miss path does not contact the phone, create an unwrap request, or consume replay state.
  Malformed supported stanzas and missing, corrupt, or otherwise unavailable private state remain
  fatal. A selected identity never falls back to another pairing or recipient mode after failure.

Protocol v2, public identity stubs, pairing state, recipient encodings, desktop key custody, and
Android/iOS authorization behavior are unchanged from beta.1. No migration or re-pairing is
required solely for this update.

The project owner confirmed the multi-identity regression on a real phone with a source-installed
desktop build on 2026-09-11. This is source acceptance; it does not certify the separately published
Windows/Android package pair. An exact-package repeat remains a post-publication follow-up.

## Installation and scope

Windows and macOS source installation is:

```console
cargo install age-plugin-phone --version 0.1.0-beta.2 --locked
```

Beta 1's limited technical-test scope and known limitations remain in force. Windows requires
Windows 11 x64 and TPM 2.0; the phone identity remains hardware-backed and every unwrap requires
fresh native verification. The optional Windows and Android artifacts were published from the same
accepted Beta 2 commit and release run. iOS remains outside external distribution scope.
