# v0.1.0-alpha.3 developer prerelease

`v0.1.0-alpha.3` is a test-signed developer snapshot of `age-plugin-phone`. It is published for
transparent evaluation of the Windows TPM plus Android StrongBox design. Publication does not
widen the supported operating scope in [`owner-only-preview.md`](../owner-only-preview.md) and
does not close the public-Alpha matrix.

## Safety boundary

- Use only synthetic or disposable data.
- Include and verify an independent recovery recipient before relying on a phone recipient.
- Expect an incompatible future upgrade to require recovery decryption, re-pairing, and
  re-encryption.
- Do not interpret LAN reachability, ADB authorization, a cable, a device name, or successful
  transport setup as authentication.
- Every successful unwrap must present a fresh Android StrongBox-backed biometric operation.

## What changed

- Existing paired phones can answer a bounded Wi-Fi discovery query authenticated with their
  StrongBox phone-signing key. The discovered address is only an untrusted delivery hint.
- Pairing can use a separate, explicit one-shot foreground Wi-Fi listener. Before a phone is
  paired, discovery is unauthenticated; the existing signed offer, StrongBox-signed response, and
  complete two-ended transcript comparison remain the pairing trust boundary.
- `auto` resolves one Wi-Fi-first route before a pairing or unwrap session exists. Explicit route
  hints remain pinned; ambiguity and every failed attempt terminate without in-flight fallback.
- Foreground Wi-Fi listeners re-arm after pairing and after completed or failed unwrap sessions
  while their lifecycle owner remains active.

## Included transports

- Developer USB through one explicitly selected ADB-authorized Android device.
- Native QR pairing and unwrap through a desktop camera.
- Explicit, default-off foreground Wi-Fi unwrap to a discovered private IPv4 address on port
  `47140`.
- One-shot, explicitly opened foreground Wi-Fi pairing.

BLE is deliberately unavailable. Wi-Fi discovery and foreground Wi-Fi provide no background wake,
authenticated route establishment, reconnect, silent retry, or availability guarantee.

## Artifact trust

The Windows ZIP is Authenticode-signed by the project's private Alpha test root. An ordinary
Windows installation does not trust that root and should show an untrusted-publisher warning. The
Android APK uses the project's registered direct-distribution signing key. Verify the release
checksums and attached signature evidence before installation.

The release page must identify one immutable commit, one workflow run and attempt, the Windows and
Android artifact SHA-256 values, and the certificate fingerprints recorded by the signing workflow.
Artifacts from different runs must never be mixed.

## Known limitations

- Protocol version 2 remains unfrozen and unsuitable for irreplaceable secrets.
- Only Windows 11 x64 with TPM 2.0 and one Android StrongBox device family has physical evidence.
- A second phone family, wrong-phone physical testing, complete invalidation/lifecycle coverage,
  publicly trusted Windows signing, and an external technical-user Alpha remain deferred.
- The exact signed package pair must pass the release-specific physical regression before this
  prerelease is published.
