# v0.1.0-alpha.5 developer prerelease

This interim experimental release adds macOS source-built hardware custody and
completes the current implementation batch. Additional macOS physical acceptance
is deferred by the [2026-09-10 scope decision](../macos-release-scope-decision.md);
unverified rows are not reported as passes. The next development stage implements
the [tagged-recipient PRD](../tagged-recipient-prd.md). This release does not include
`age1tag` or `p256tag` support; `age1phone` remains the recipient format.

## Changes since alpha.4

- Four independently packaged desktop crates separate protocol, platform keys,
  platform storage and the CLI. All internal dependencies use exact versions.
- macOS uses separate Secure Enclave signing and agreement keys through an archived
  Swift/CryptoKit bridge, with no software-key fallback. Source installation needs
  Rust 1.88+ and Xcode Command Line Tools; no Developer ID certificate is required.
- macOS private storage validates ownership, ACLs, links and directory identity,
  uses descriptor-relative operations and full synchronization, and preserves
  uncertain replay state instead of resetting it.
- Managed and explicit pairing use ownership journals; setup resume, normal and
  orphan cleanup preserve exact-target boundaries and interrupted state.
- macOS Wi-Fi discovery handles compact netmasks, source-interface broadcasts and
  response polling. Android foreground Wi-Fi listeners own discovery reception.
  Bounded diagnostic output distinguishes discovery failures without raw payloads.

## Installation and artifacts

After the four crates.io packages are published:

```console
cargo install age-plugin-phone --version 0.1.0-alpha.5 --locked
```

The GitHub prerelease ships the existing Windows x64 test-signed ZIP, Android arm64
APK, checksums and signature records. macOS is source-only; no macOS installer or
signed iOS distribution is included. Windows uses the private Alpha test root,
which ordinary Windows installations do not trust. Verify the attached provenance
and checksums before installing.

## Evidence and scope

The [M6 record](../macos-m6-evidence.md) identifies the exact earlier candidate
artifacts and native observations: Android USB/Wi-Fi and iPhone Wi-Fi age/rage
roundtrips, QR success, cancellation and fresh-verification recovery, selected
lifecycle failures, independent recovery and Android cleanup. These records do
not constitute a fresh physical run on the alpha.5 signed assets.

The measured Mac is MacBookPro18,3 / arm64 / macOS 26.6.2 (25G83), in a logged-in
session. Other hardware/OS, GUI callers and remaining physical rows stay unverified.
macOS 14 is a build deployment floor, not a tested minimum support version.

Existing paired phone v2 state is not migrated or replaced by this release. Old
macOS software desktop state is rejected by the hardware product path; use the
[recovery guide](../macos-recovery.md) before changing existing state. Restoring
older valid desktop replay snapshots is not detected on Windows or macOS; stronger
protection is deferred. Reference deletion is local cleanup, not irreversible
hardware-key destruction. Phone revocation remains a separate operation.

Fresh native phone verification, complete pairing fingerprint comparison, session
binding and durable consumption remain required. This is an owner technical preview
for disposable data with an independently verified recovery recipient, not a full
macOS support, public-Alpha, frozen-protocol or production-secrets claim.
