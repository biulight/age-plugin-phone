# v0.1.0-beta.1 limited technical beta

Candidate release notes — not yet published. Publication remains gated by the
[beta closeout checklist](../beta-readiness.md). Use synthetic or disposable data
with a separately verified independent recovery recipient; production secrets are
not supported.

## Changes since alpha.5

- Explicit `--recipient-type tag` on setup/pair and public-only `recipients` export
  produce native `age1tag` addresses. age 1.3+ can encrypt without the phone plugin.
  The default stays `phone`; tag selection has different public visibility.
- Android StrongBox and iOS Secure Enclave open `p256tag` through the existing
  signed, replay-consumed, fresh-verification path. Malformed stanzas and ambiguous
  identities fail closed; failure never switches pairing or recipient mode.
- iOS native authentication now has an operation-specific deadline. Expiry closes
  the fresh authentication context and prevents late completion from returning a
  file key. The observed physical timeout regression was fixed and retested.

## Installation and distribution

After publication, Windows and macOS source installation is:

```console
cargo install age-plugin-phone --version 0.1.0-beta.1 --locked
```

Windows builds require MSVC Rust and Visual Studio C++ Build Tools / Windows SDK;
macOS builds require Xcode Command Line Tools. See the [build prerequisites](../crates-io-release.md).
Source installation does not require trusting the private Windows signing root.
Windows still requires Windows 11 x64 and TPM 2.0 at runtime.
Follow the [Windows Beta quick start](../windows-beta-quickstart.md) for setup and
synthetic phone/recovery validation.

Planned optional Windows binary assets and Android delivery are the Windows x64
test-signed ZIP, Android ARM64 signed APK, checksums and signature records.
Ordinary Windows installations do not trust the
private signing root. Do not import that root into a system trust store. macOS is
source-only; no macOS installer or externally installable iOS distribution is
included. iPhone observations apply to the existing development-device cohort.

## Compatibility and evidence

Update the phone app before selecting tag; old mobile parsers strictly reject it.
Protocol v2, public stubs, pairing state and setup JSON schema 1 are unchanged, but
the protocol remains unfrozen. Future prerelease upgrades may require re-pairing
and recovery-based re-encryption; general downgrade compatibility is not promised.
See the [tag quick start](../tagged-recipient-quickstart.md) for format selection.

The [implementation record](../tagged-recipient-evidence.md) includes physical
Android/iPhone candidate tests, Windows-to-Android Wi-Fi, mixed phone/SE/recovery
recipients and Shine 2.0.3 integration. Those exact earlier artifacts retain their
scope; final beta-package tests and remaining mandatory physical checks are still
pending. No full-device-matrix or retained old-ciphertext migration pass is claimed.

The validated transport scope proposed for this beta is Developer USB on Android
and foreground Wi-Fi on the recorded devices. QR tag, BLE and background wake are
outside that scope. Windows and macOS do not guarantee detection of restored older
valid desktop replay snapshots. Fresh phone verification, durable consumption and
complete response/session binding remain mandatory.
