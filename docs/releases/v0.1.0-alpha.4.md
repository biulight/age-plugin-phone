# v0.1.0-alpha.4 developer prerelease

These notes describe the alpha.4 candidate. Publication requires the immutable commit, signing run,
artifact digests, and exact-package physical acceptance in the
[alpha.4 checklist](../alpha.4-acceptance-checklist.md). The notes alone are not acceptance evidence;
the publishing workflow appends the verified artifact provenance to the release body.

`v0.1.0-alpha.4` retains the [owner-only preview](../owner-only-preview.md) scope: one known
Windows 11 x64 TPM desktop and one qualified Android StrongBox phone, synthetic or disposable data,
and an independently verified recovery recipient. Protocol v2 remains experimental and unfrozen.

## Changes since alpha.3

- USB and Wi-Fi pairing display loading feedback and prevent duplicate submissions.
- Android Activity-stop cleanup cancels pending pairing, native fingerprint confirmation, USB,
  Wi-Fi and authentication resources. Returning to the app permits a new exchange without restoring
  cancelled requests or resetting replay state. Wi-Fi UI handoff also rejects stale completion.
- Windows `wifi-doctor` runs one bounded discovery window and reports coarse stages and outcomes.
  The ZIP includes the Wi-Fi guide and exact-program/interface firewall helper.
- The Windows minimum acceptance script checks synthetic recovery, repeated USB authorization,
  cancellation and fresh retry, foreground Wi-Fi, background interruption, final pause, and reverse
  rule absence. Fail-closed native Windows dialogs collect READY and OBSERVED confirmations without
  depending on terminal stdin. Operator observations remain required; its report alone does not
  approve release.
- Experimental iOS 17+ source adds Secure Enclave custody, per-operation Face ID/Touch ID, native QR
  and foreground Wi-Fi, Swift vectors, simulator compilation, and app icons. This candidate ships
  only Windows and Android artifacts; iOS has no signed distribution or physical acceptance claim.

## Authentication and transport boundary

Every phone unwrap requires fresh native hardware-bound biometric verification. Pairing requires
the complete signed transcript fingerprint comparison on both endpoints. Loading indicators,
transport reachability, ADB authorization, discovery, and firewall configuration provide no
authorization. Failures terminate the request; a fresh retry never restores consumed replay state.

Developer USB, native QR, and default-off foreground Wi-Fi remain the implemented transports.
`auto` makes one Wi-Fi-first route decision before a session begins. BLE is unavailable. There is
no background wake, reconnect, silent retry, or availability guarantee.

## Artifact trust and remaining evidence

Windows packages use the private Alpha test root and remain untrusted on ordinary Windows
installations. Android packages use the registered direct-distribution signer. Verify the exact
commit, signing run and attempt, package/EXE hashes, and certificate fingerprints before installation;
never mix artifacts from different runs. No trust-root installation is part of acceptance.

The alpha.3 signed-package report and the subsequent isolated `.wifipoc` debug UI/Wi-Fi report are
historical evidence only. The sporadic foreground discovery failure was not reproduced in the
bounded follow-up and remains unexplained; a default-environment or clean-VM pass is not established.
The alpha.4 signed normal APK and ZIP must complete fresh physical regression before publication.

Second-device-family, wrong-phone/multi-phone, full QR/replay and lifecycle/invalidation coverage,
public Windows signing, and external-user Alpha gates remain deferred. See the
[full matrix](../alpha-matrix.md), [quickstart](../windows-alpha-quickstart.md),
[changelog](../../CHANGELOG.md), and [security policy](../../SECURITY.md).
