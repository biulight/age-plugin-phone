# v0.1.0-beta.3 maintenance candidate

This candidate targets owner testing on Windows x64 and Android ARM64 with synthetic data and a
separately verified recovery recipient. The signed package pair and its device acceptance are pending.

## Changes since Beta 2

- Android foreground Wi-Fi discovery now re-arms when network access returns. The first discovery
  after an idle network change and after an interrupted approval passed on an earlier repair APK.
  The candidate must repeat both cases with its own signed APK.
- This is the first candidate targeting frozen protocol v2, suite 1. The implementation baseline
  is `41dd48d`; `6206d79` records the final specification and eleven public vectors. Endpoints
  enforce the 65,536-byte signed-envelope limit and the 300-second expiry window.
- In the iOS source build, an invalid system clock rejects the operation. A corrupt private
  replay capacity returns a decoding error and preserves the stored record. External iOS
  distribution remains outside this candidate's scope.

## Upgrading the test pair

Before updating either endpoint, decrypt a retained synthetic sample with its independent recovery
recipient. For the candidate exercise, update the desktop first, then update the same-signer
Android app in place. Preserve the existing pairing and check the same sample with fresh native
phone verification. The recorded Alpha 5 upgrade exercised this order on a separate test pair.
Beta 2 to Beta 3 still requires verification on the signed candidate packages.

If a pairing must be replaced, compare the full fingerprint on both endpoints. Retained
phone-format ciphertext needs the independent recipient and re-encryption for the new pairing.
See the [recovery guide](../manual/guides/recovery.md).

## Exact-package acceptance before publication

- Bind the immutable source SHA, workflow run and attempt, signatures and installed hashes of the
  Windows test-signed package and Android APK. Use those same artifacts for every row below.
- Verify independent recovery and both `phone` and `tag` multi-identity selection. A valid
  nonmatch must allow the matching identity to proceed with fresh verification.
- On foreground Wi-Fi, exercise idle network loss and loss during a pending authorization.
  Each first automatic discovery after restoration must work without a direct-address probe,
  listener toggle or second attempt. Record zero output for the interrupted request.
- Cancel a request, confirm app-process restart, then replay the unexpired signed request.
  Require rejection without another biometric prompt or decrypted output. A fresh request must
  require new verification and recover the expected sample. Exercise explicit Developer USB
  recovery on a new request.

The [maintenance evidence](../beta-readiness.md) records the published Beta 2 behavior and the
earlier repair results. The [signing procedure](../release-signing.md) binds physical acceptance
and publication to the same build artifacts.
