# v0.1.0-alpha.1 developer prerelease

`v0.1.0-alpha.1` is the first installable, test-signed developer snapshot of
`age-plugin-phone`. It is published for transparent evaluation of the Windows TPM plus Android
StrongBox design. Publication does not widen the supported operating scope in
[`owner-only-preview.md`](../owner-only-preview.md) and does not close the public-Alpha matrix.

## Safety boundary

- Use only synthetic or disposable data.
- Include and verify an independent recovery recipient before relying on a phone recipient.
- Expect an incompatible future upgrade to require recovery decryption, re-pairing, and
  re-encryption.
- Do not interpret LAN reachability, ADB authorization, a cable, a device name, or successful
  transport setup as authentication.
- Every successful unwrap must present a fresh Android StrongBox-backed biometric operation.

## Included transports

- Developer USB through one explicitly selected ADB-authorized Android device.
- Native QR pairing and unwrap through a desktop camera.
- Explicit, default-off foreground Wi-Fi unwrap to a numeric private IPv4 address on port `47140`.

BLE is deliberately unavailable. Foreground Wi-Fi provides no discovery, background service, cold
start, authenticated route establishment, reconnect, silent retry, or fallback.

## Artifact trust

The Windows ZIP is Authenticode-signed by the project's private Alpha test root. An ordinary
Windows installation does not trust that root and should show an untrusted-publisher warning. The
Android APK uses the project's registered direct-distribution signing key. Verify the release
checksums and the attached signature evidence before installation.

The release page must identify one immutable commit, one workflow run and attempt, the Windows and
Android artifact SHA-256 values, and the certificate fingerprints recorded by the signing
workflow. Artifacts from different runs must never be mixed.

The published artifact pair is bound to commit
`be1e85e364e67a55ab750f72c591205014ea1938` and signing workflow `33671049489`, attempt 1:

- Windows executable SHA-256:
  `857c7bc19fd8961d0b41652edee0a7334f0f4186932eec220105b0e01c0210e5`
- Windows ZIP SHA-256:
  `5c0b44334d39ea933aa1d207d962df21bfd4c981577409ae566048430daebbff`
- Android APK SHA-256:
  `68d75747596b4c20f91af866343dd85d15bcf05496b2eadd83e814b9b97d1014`

On the recorded Windows 11 x64 TPM and Android 16 StrongBox devices, those exact packages passed a
fresh identity and full-fingerprint Developer USB pairing, one fresh-biometric Developer USB
unwrap, an independent-recovery decrypt of the same synthetic ciphertext, and one explicit
foreground Wi-Fi unwrap. The Wi-Fi listener was observed open only in the foreground, closed after
backgrounding, resumed after returning to the foreground, and closed again after the persisted
mode was paused. The final ADB reverse-rule count was zero. This is the deliberately small
developer-prerelease regression; it does not transfer or waive the remaining public-Alpha matrix.

## Known limitations

- Protocol version 2 remains unfrozen and unsuitable for irreplaceable secrets.
- Only Windows 11 x64 with TPM 2.0 and one Android StrongBox device family has physical evidence.
- A second phone family, wrong-phone physical testing, complete invalidation/lifecycle coverage,
  publicly trusted Windows signing, and an external technical-user Alpha remain deferred.
- Foreground Wi-Fi has now passed the minimal exact-signed-package regression above. Discovery,
  background operation, reconnect, route authentication, silent retry, and fallback remain out of
  scope.
